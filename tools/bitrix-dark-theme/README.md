# Генератор тёмной темы Битрикса

Собирает `public/assets/bitrix-dark-theme.js` — скрипт функции «Тёмная тема Битрикса» (`bitrixDarkTheme` в `src/js/options.js`).

Тема — это **статичный снимок** CSS, который Dark Reader генерирует для стилей Битрикса, плюс ручные правки. Живой Dark Reader пересчитывает стили на лету при каждом изменении страницы, поэтому тормозит на тяжёлом Битриксе. Здесь эта работа делается один раз при сборке, а на странице остаётся только вставить готовый CSS.

## Запуск

```bash
npm run build-dark-theme   # из корня проекта
```

- Зависимости генератора (`darkreader`, `puppeteer-core`) ставятся автоматически обычным `npm install` в корне — через `postinstall`.
- Нужен доступ к порталу (`PORTAL_ORIGIN` в `lib/shared.mjs`) и установленный Chrome. Chrome ищется по стандартным путям macOS и Linux, иначе путь берётся из переменной `CHROME_PATH`:
  ```bash
  CHROME_PATH="/path/to/chrome" npm run build-dark-theme
  ```
- Занимает около минуты.
- Результат не хранится в гите (как `content-styles.css`). `npm run dev` собирает тему сам, если файла нет. `npm run build` её не собирает, а только предупреждает, если файла нет.

Пересобирать тему стоит после обновления Битрикса на портале, после правок в `config/extra.css`, `config/paths.json` или в скриптах генератора.

## Как это работает

Шаги запускаются по очереди (`npm run build` в `package.json` этой папки):

| Шаг | Скрипт | Что делает | Результат |
|---|---|---|---|
| 1 | `scripts/fetch.mjs` | Скачивает CSS-файлы из `config/paths.json` (6 потоков, повторные попытки) | `build/css/` |
| 2 | `scripts/generate.mjs` | Открывает в headless Chrome пустую страницу с этими стилями, запускает на ней Dark Reader и забирает его CSS через `exportGeneratedCSS()` | `build/darkReader.css` |
| 3 | `scripts/rgbVariables.mjs` | Цвета вида `rgba(var(--…-rgb), a)` — Dark Reader их не распознаёт как цвета | `build/rgbVariables.css` |
| 4 | `scripts/masks.mjs` | Иконки-маски (`mask-image`): в экспорте Dark Reader они становятся тёмными — инвертируем | `build/masks.css` |
| 5 | `scripts/icons.mjs` | Тёмные SVG-иконки фоном: живой Dark Reader перекрашивает их на лету, статичный CSS — нет. Перекрашиваем в светлые | `build/icons.css` |
| 6 | `scripts/pack.mjs` | Склеивает всё + `config/extra.css`, чинит потерянные CSS-переменные, сжимает (`lib/minify.mjs`) и упаковывает в скрипт | `public/assets/bitrix-dark-theme.js` |

Промежуточные файлы складываются в `build/` и в гит не попадают. Шаги можно запускать и по отдельности (`node scripts/icons.mjs`) — из любой папки, пути считаются от папки инструмента.

### Что делает скрипт темы на странице

Скрипт регистрируется контент-скриптом на `document_start` только пока функция включена (`src/background/darkTheme.js`), поэтому страница не мелькает белым. В уже открытые вкладки service worker при включении подкладывает тот же скрипт через `chrome.scripting.executeScript`, а при выключении шлёт в документ событие `pts-bitrix-dark-theme-toggle` (`detail: false`). Выключенная тема остаётся в DOM: её `<style>` получают `media="not all"`, класс `.pts-bitrix-dark` снимается, пересчёт новых таблиц стилей продолжается. Повторный запуск скрипта в том же документе включает её обратно, ничего не разбирая заново.

1. Ставит на `<html>` класс `.pts-bitrix-dark` — по нему `src/css/content-styles.css` правит элементы самого расширения.
2. Вставляет `<style id="pts-bitrix-dark-theme">` и держит его последним ребёнком `<html>`, после `<body>`: Битрикс кладёт стили и в `<body>`, а при равной специфичности побеждает тот, что ниже.
3. **Подстраховка** (`runtime/runtime.js`): таблицы стилей, которых нет в снимке (кастомные компоненты портала, склейки из `/bitrix/cache/`, модули, которые Битрикс подгружает по требованию), один раз пересчитываются — порциями в отдельные `<style data-pts-bitrix-dark-theme-dynamic>` между `<body>` и основным стилем темы (дописывание в один тег заставляло бы браузер каждый раз разбирать весь накопленный CSS). Явные цвета пересчитываются упрощённым алгоритмом, а переменные портала `var(--X)` (в том числе с запасным значением) подменяются тёмными версиями из снимка Dark Reader (`--pd-text--X`, `--pd-bg--X`, `--pd-border--X`) — так лениво подгружаемые модули получают те же цвета, что и остальные. За всем DOM и inline-стилями не следит — только за появлением `<link>`/`<style>`. Стили самого расширения не трогает: `<style data-pts>` (их ставит `insertCSS`), `<style data-primevue-style-id>` от PrimeVue и `chrome-extension://`-ссылки — у виджетов своя тёмная тема, а перекрашенная копия перебила бы цвета, выбранные пользователем.

CSS лежит строкой внутри JS, а не отдельным `.css`, чтобы вставить его синхронно и управлять порядком стилей.

## Файлы

```
tools/bitrix-dark-theme/
├── config/              правится руками
│   ├── paths.json       список таблиц стилей портала, из которых собирается снимок
│   └── extra.css        ручные правки поверх Dark Reader — дописываются последними и побеждают
├── scripts/             шаги сборки по порядку (см. таблицу выше)
├── lib/
│   ├── shared.mjs       общее: адрес портала, палитра, пути, чтение config/paths.json и build/css/
│   └── minify.mjs       сжатие CSS без изменения результата
├── runtime/
│   └── runtime.js       код подстраховки для страницы
└── build/               промежуточные файлы сборки (в .gitignore)
```

- **`lib/minify.mjs`** — сначала своё (замена неопределённых зацепок Dark Reader `var(--pd-text-000000, цвет)` самим цветом, склейка четырёх одинаковых `border-*-color`, лишние пробелы), затем Lightning CSS. Правила, которые он не смог разобрать, выводятся предупреждением в консоль сборки.
- **`runtime/runtime.js`** — **не самостоятельный файл**: `scripts/pack.mjs` вставляет его в скрипт темы и подставляет список из `config/paths.json` вместо метки `/* @known-stylesheet-paths */ []`.

## Как править тему

**Что-то выглядит не так** — добавьте правило в `config/extra.css` и пересоберите тему. Перед правилом — комментарий, что чинится и почему Dark Reader с этим не справился. Обычно нужен `!important`: правила Dark Reader и Битрикса часто специфичнее.

**Наш собственный элемент** (виджет, кнопка расширения) — правьте не здесь, а в `src/css/content-styles.css` под классом `.pts-bitrix-dark`. Если правило темы перебивает цвет фичи (так было с подсветкой карточек: `config/extra.css` красит `.tasks-kanban-item` с `!important`), дайте фиче своё правило `.pts-bitrix-dark …` с большей специфичностью. Фичам, которые красят фон в цвет из настроек, для этого есть `prefixBitrixDarkSelector()` и `getBitrixDarkBackground()` в `src/js/utils.js` — см. `user-name-color`, `quote-color`, `kanban-user-cards`.

**Какой-то модуль остался светлым целиком** — скорее всего, его CSS нет в `config/paths.json`. Особенно это касается того, что Битрикс подгружает только по действию пользователя (окно пользователя, учёт времени, вход по QR): со страницы при загрузке такие файлы не видны — откройте нужное окно и только потом смотрите список стилей. Найдите путь на странице портала (DevTools → Network → фильтр CSS, или в консоли `[...document.styleSheets].map((sheet) => sheet.href)`) и добавьте в `config/paths.json`. Правила для списка:

- **Только стандартные пути**: `/bitrix/js/…`, `/bitrix/components/bitrix/…`, `/bitrix/templates/bitrix24/…`. Расширение работает на любом Битрикс24, а не только на нашем портале.
- **Не добавляйте склейки из `/bitrix/cache/css/…`**: в их имени хэш, который меняется при пересборке кэша, и файл перестанет скачиваться. Вместо склейки добавьте её исходники — их пути перечислены в самой склейке комментариями вида `/* /bitrix/components/bitrix/…/style.min.css */`.
- **Не добавляйте кастом конкретного портала** (`/local/…`, `/js/…`) — его подхватит подстраховка.
- Порядок важен: при равной специфичности побеждает правило из файла, который стоит ниже.

**Палитра** — `PALETTE` в `lib/shared.mjs` (фон `#22272e` — как у тёмной темы GitHub dimmed, текст `#cdd9e5` — ярче, чем там). `runtime/runtime.js` повторяет её своими числами — при смене палитры поправьте и его. Цвета в `config/extra.css` и `src/css/content-styles.css` подобраны под ту же палитру.

## Если что-то пошло не так

- **«не скачался … (HTTP 404)»** — файла больше нет на портале (Битрикс убрал или переименовал модуль). Уберите путь из `config/paths.json` или замените новым.
- **«Не скачался ни один CSS-файл»** — нет сети или доступа к порталу.
- **«Chrome не найден»** — укажите путь в `CHROME_PATH`.
- **«Dark Reader выдал всего N байт CSS»** — Chrome не смог загрузить стили с портала.
- **В консоли страницы ошибка из `bitrix-dark-theme.js`** — сломался `runtime/runtime.js`; основной CSS темы при этом обычно применяется, отказывает только подстраховка.

## Ограничения

- Снимок привязан к версии Битрикса на портале, с которого снимался. На порталах с другой версией (например, облачный Битрикс24 обычно новее коробки) часть новых классов может остаться светлой. Подстраховка такие файлы не пересчитывает: их пути уже есть в снимке.
- Цвета, которые Битрикс ставит прямо в разметку (inline-стили), снимок не меняет — для заметных мест есть правки в `config/extra.css`.
- Фон-тема портала: в `config/paths.json` есть `themes/light/galactic-harmony/style.css` — оформление, выбранное у нас. Фон других тем затемнит только подстраховка.
